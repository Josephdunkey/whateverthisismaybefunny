0. 一分钟看懂

你原来的想法是：“我喂给 agent 很多书，它就能像读过书的人一样，看到一条新闻后用书里的内容回答我。” 这个项目就是把这个想法做成一套可运行的系统。

如果你现在就想跑起来，先照抄这 4 步（其余章节都是解释）：
  1. 确认 Ollama 在跑：浏览器打开 http://127.0.0.1:11434/api/tags，能看到模型列表。
  2. 确认 Hindsight 在跑：浏览器打开 http://127.0.0.1:8888/health，能看到 "status":"healthy"。没起来就按第 4 节启动。
  3. 启动书库 GUI：打开 PowerShell，执行下面两行，然后浏览器打开 http://127.0.0.1:8765/。 
    cd C:\Users\mybea\projects\bookcompiler
.\.venv\Scripts\python.exe -m bookcompiler.cli --db .bookcompiler\library.db gui --open
  4. 启动 Hermes：另开一个 PowerShell 窗口，执行下面两行，然后直接输入问题。 
    $env:HERMES_HOME='D:\hermes agent'
& 'D:\hermes agent\bin\hermes.exe' chat

注意：命令要输在 PowerShell 窗口里，不是浏览器地址栏。第 3 步的窗口不要关，关了 GUI 就停了。第一句话可以问：“用我读过的书分析：降准是否必然导致银行信贷扩张？请给出书名、页码和逐字引用。”

BookCompiler

“图书馆 + 索引卡 + 引用检查员”

负责把本地书导入、切片段、建索引、抽取书卡/框架卡、做混合检索、跨书实体对齐、命题图谱、引用校验和受控自进化。它本身不是聊天机器人，而是给 agent 提供“有出处的书库能力”。

Hermes Agent

“会说话、会调用工具的研究助理”

负责和你对话、理解问题、决定调用哪些工具、组织最终回答。它通过 MCP 调用 BookCompiler 和 Hindsight。它自己还有会话、技能和自进化机制。

Hindsight

“跨对话的长期记忆笔记本”

负责保存用户偏好、纠正、失败教训和结果，不保存整本书。它有自己的数据库、Embedding、召回和（实验性的）reflect。BookCompiler 和 Hermes 都可以接它。

1. 先把术语说成人话

下面这些词你会在教程和配置里反复看到。先用类比理解，不需要背。

术语人话解释在这个项目里对应什么
Agent（智能体）会自己决定“下一步做什么”的 AI 程序，不只是被动回答问题。Hermes Agent。
MCPModel Context Protocol，可以理解成“AI 工具的 USB-C 接口”。只要工具按这个协议暴露，任何支持 MCP 的 agent 都能调用。BookCompiler 的 19 个工具、Hindsight 的 36 个工具。
stdio MCPMCP 的一种连接方式：宿主（Hermes）启动一个本地子进程，通过标准输入/输出和它说话。Hermes 调用 BookCompiler 的 Python 进程。
HTTP MCPMCP 的另一种连接方式：通过 HTTP 地址连接一个已经在运行的服务。Hermes 连接 Hindsight 的 /mcp/... 地址。
RAGRetrieval-Augmented Generation：先检索资料，再让模型基于资料回答。类比“开卷考试”。BookCompiler 的检索层 + 引用校验。
Embedding（嵌入）把一段文字变成一串数字（向量），意思相近的文字在数学空间里更接近。类比“给每句话一个坐标”。BGE 模型把 chunk 变成 512 维向量。
向量数据库专门存向量并做相似度搜索的数据库。不是所有项目都必须单独用一个。BookCompiler 把向量直接存在 SQLite 里；Hindsight 用 PostgreSQL + pgvector。
BM25一种经典的关键词检索算法，擅长精确词、术语、数字、专名。混合检索的一部分。
混合检索同时用关键词（BM25）和语义向量（Embedding），再加实体扩展，最后融合分数。BookCompiler 的默认检索方式。
Reranker（重排器）先粗召回一批候选，再用更贵的模型重新排序。本机已下载 bge-reranker-base，但当前检索配置显示 rerank: null，没有证明它比 hybrid 更好。
Chunk（片段）把一本书切成适合检索的小段。当前 8,741 个 chunk。
Citation（引用）回答里引用书中的原话，并给书名、章节、页码。quote 必须能在原文里逐字找到，否则校验失败。
Claim（命题）从原文抽出的“主语—谓语—宾语”式主张，例如“降准会增加基础货币”。claims 表；当前 640 条。
Supersession新证据取代旧主张。旧命题标记为 superseded，但保留历史，可回滚。需要显式确认，不会自动改判。
Entity（实体）书里反复出现的概念、机构、政策、变量等。entities 表；当前 92 个规范实体。
实体对齐把不同书里对同一个东西的不同叫法合并，例如“央行 / 中国人民银行 / PBoC”。规则 + 别名组 + 保守包含关系；不自动猜同义词。
SQLite一个文件就是一个数据库，零安装、单机、适合个人项目。BookCompiler 的 library.db、Hermes 的 state.db。
PostgreSQL更强大的服务器型数据库，适合并发、复杂查询和扩展。Hindsight 的内嵌 PostgreSQL。
pgvectorPostgreSQL 的向量扩展，让数据库能存向量并做相似度搜索。Hindsight 用它存记忆向量。
Hindsight BankHindsight 里的“记忆分区/命名空间”。不同 bank 互不混淆。hermes 存个人偏好/项目上下文；bookcompiler 存书库教训。
retain / recall / reflectHindsight 的三个动作：记住、召回、综合反思。retain/recall 已实测；reflect 未验证。
Ollama本地运行大模型和小模型的服务器，提供 OpenAI 兼容接口。http://127.0.0.1:11434。
Skill（技能）给 agent 的一段“何时用、怎么用工具”的说明书。Hermes 的 book-library 技能。

2. 总体架构

不要把三套系统想成一坨。它们是三个独立的进程/服务，通过文件和网络接口连接。

用户
 ├─ 浏览器 → BookCompiler GUI（127.0.0.1:8765）
 │              ├─ SQLite：library.db
 │              │    ├─ 书 / chunk / 原文
 │              │    ├─ 向量（chunk_embeddings）
 │              │    ├─ 书卡 / 框架卡 / 分析
 │              │    ├─ 实体 / 提及 / 关系
 │              │    ├─ 命题 / 证据 / 冲突
 │              │    └─ 反馈 / 记忆 / 进化状态
 │              └─ HTTP → Hindsight（127.0.0.1:8888）
 │
 ├─ Hermes Agent（D:\hermes agent）
 │      ├─ SQLite：state.db（会话、消息、系统提示、状态）
 │      ├─ MCP stdio → BookCompiler（19 个工具）
 │      ├─ MCP HTTP  → Hindsight /mcp/hermes/（36 个工具）
 │      └─ MCP HTTP  → Hindsight /mcp/bookcompiler/（36 个工具）
 │
 ├─ Hindsight API（127.0.0.1:8888）
 │      ├─ 内嵌 PostgreSQL（127.0.0.1:5432）
 │      │    ├─ 数据库：hindsight
 │      │    ├─ 扩展：pgvector 0.8.5
 │      │    └─ 数据目录：C:\Users\mybea\.pg0\instances\hindsight\data
 │      └─ 调用 Ollama（127.0.0.1:11434）
 │           └─ qwen2.5:7b-instruct-q4_K_M
 │
 └─ Ollama（127.0.0.1:11434）
        └─ 模型文件：D:\models（blobs / manifests）

三条数据流

  1. 书 → 证据：书被导入 BookCompiler，切成 chunk，建 BM25 和向量索引。回答书里的内容时，必须从这里取原文。
  2. 经验 → 记忆：用户反馈、纠正、偏好写入 BookCompiler 的 feedback/memory，并异步写入 Hindsight 的 bookcompiler bank。
  3. 对话 → 调用：Hermes 根据问题调用 BookCompiler 工具，必要时再调用 Hindsight 召回长期偏好，最后组织回答。
关键设计：书里的原文和精确引用永远留在 BookCompiler 的 SQLite；Hindsight 只存“跨任务可复用的教训/偏好”，不存整本书。这样不会把“记忆”变成“二手摘要”，也不会让模型拿记忆冒充原文。

4. 启动顺序（最重要）

正确的启动顺序是：Ollama → Hindsight → BookCompiler GUI → Hermes。后面依赖前面。不要一上来就开 Hermes，否则它可能连不上书库或记忆。

1

启动 Ollama

Ollama 通常已经在后台运行。先检查：

Invoke-RestMethod http://127.0.0.1:11434/api/tags | Select-Object -ExpandProperty models | Select-Object name

如果报“无法连接”，打开开始菜单里的 Ollama，或者在 PowerShell 里运行：

ollama serve

看到模型列表里有 qwen2.5:7b-instruct-q4_K_M 就说明正常。

2

启动 Hindsight

进入 Hindsight 目录，用 run_server.py 启动。不要直接运行 hindsight-api.exe，否则 Windows 的 GBK 控制台可能报 UnicodeEncodeError。

cd D:\hindsight
.\.venv\Scripts\python.exe .\run_server.py

这个命令会占住当前窗口。日常使用时另开一个 PowerShell 窗口即可；本机当前已经有一个 Hindsight 进程在运行，所以通常不需要重复启动。

检查是否成功：

Invoke-RestMethod http://127.0.0.1:8888/health

正常输出类似：

status        database
------        --------
healthy       connected

如果 8888 没监听，先看日志：

Get-Content -Tail 80 -Encoding UTF8 D:\hindsight\server.log
3

启动 BookCompiler GUI

cd C:\Users\mybea\projects\bookcompiler
.\.venv\Scripts\python.exe -m bookcompiler.cli --db .bookcompiler\library.db gui --host 127.0.0.1 --port 8765 --open

如果不想自动开浏览器，去掉 --open。然后打开：

http://127.0.0.1:8765/

检查 API：

Invoke-RestMethod http://127.0.0.1:8765/api/status | ConvertTo-Json -Depth 6

应该能看到 version: 0.5.1、books: 12、compiled_books: 4，以及 hindsight.reachable: true。

4

启动 Hermes

$env:HERMES_HOME='D:\hermes agent'
& 'D:\hermes agent\bin\hermes.exe' doctor
& 'D:\hermes agent\bin\hermes.exe' chat

第一次建议先跑 doctor，确认 Python、模型、MCP 都正常。然后进入聊天界面。

5. BookCompiler 网页 GUI：每个页面怎么用

打开 http://127.0.0.1:8765/。左上角是导航，右上角显示版本和数据库路径。GUI 只绑定 127.0.0.1，没有登录系统，所以只在本机用。

5.1 总览（Overview）

  • 看“入库书 / 已编译 / 判断框架 / 分析 / 反馈 / 进化提案”的数量。
  • 看“学科覆盖”和“分析视角”的柱状图。
  • 看“Hindsight 长期记忆”卡片：是否 connected、bank 名、bank 是否存在。
  • 看“最近分析”。点一条可以打开详情。

5.2 书库（Library）

这是最常用的页面。

  1. 点右上角“导入本地书”。
  2. 填写文件路径，例如 D:\fanshu\某本书.txt。
  3. 书名可以留空，默认用文件名；作者、学科标签可选。
  4. 点“开始导入”。

导入后会显示章节数和片段数。注意：导入只是 ingested，不是 learned。要变成 learned/compiled，需要 agent 读章节、写编译补丁、执行 compile 和 validate。

书库表格里的列：

列含义
书名 / 作者书的基本信息；有书卡时会显示一句话主旨。
状态ingested 已入库；compiled 已深度编译。
学科economics / politics / law / finance 等标签。
框架这本书编译出的 FrameworkCard 数量。
片段chunk 数量。
导入时间入库时间。

5.3 分析（Analyze）

这个页面负责“选题 + 选书 + 生成分析草稿”。它不是大模型聊天框，不会自己写出完整答案；完整分析补丁要由 agent（Hermes）写，再由系统校验。

  1. 选择模式：
    • auto：agent 自动匹配书和框架，不需要额外同意。
    • direction：你给一个方向，例如“地方债务与银行风险”。
    • books：你直接指定书和/或框架。
  2. 填写问题/新闻/事件。
  3. 勾选分析视角：经济、政治、法律、通用。
  4. 点“生成选择卡”。系统会显示指定的书、推荐补充的书、指定的框架、推荐补充的框架、推荐理由、覆盖缺口，以及“信息源缺口提示”：如果问题需要《中国人民银行法》等权威原文而书库没有，会直接给出下载说明和入库命令。
  5. 如果是 direction 或 books 模式，必须在选择卡下方三选一：
    • specified：只用你指定的范围；
    • specified+recommended：指定 + agent 推荐；
    • recommended：只用 agent 推荐。
  6. 点“生成分析草稿”。系统会创建 AnalysisPacket 草稿，包含假设、证据、冲突、引用等结构。
  7. 草稿的 conclusion / counterevidence / citations 需要 agent 补齐，再通过 analysis-apply 或 API 写回并校验。
同意门的意义：模式 2/3 不允许 agent 偷偷扩大范围。你选“只用指定的”，它就只能用指定的；想加推荐书，必须你明确点“指定 + 推荐”。修改问题、方向、视角、书或框架后，旧同意会自动失效。

5.4 记忆（Memory）

输入问题，点“召回”。它会显示本地 feedback / memory 里的教训，以及 Hindsight bookcompiler bank 里的长期偏好/纠正（如果可用）。

记忆不是事实来源。它只告诉你“用户以前纠正过什么、偏好什么、哪些错误别再犯”，不能替代书里的原文引用。

5.5 自进化（Evolution）

点“从反馈生成提案”。系统会把重复错误、偏好、缺失证据聚合成 proposal。状态流转是：

proposed → accepted → shadow → promoted → rolled_back
        ↘ rejected

晋升不是点一下就行：必须有结构回放报告，且所有 case 通过。它只允许改检索权重、书偏好、框架偏好，不会自动改书卡、引用、prompt 或代码。

5.6 实体（Entities）

  • 搜索实体、别名，例如“融资平台”“降准”“央行”。
  • 勾选“只看跨书”，查看跨书实体。
  • 点“近似重复审计”，查看“资产负债表 ↔ 央行资产负债表”这类候选。
  • 在“待确认实体合并”卡片里：
    • “扫描合并候选”：重新扫描并保存候选；
    • “刷新候选”：只刷新列表；
    • “确认合并”：移动 mention/relation/claim，可撤销；
    • “拒绝”：保留为两个不同实体；
    • “撤销合并”：恢复合并前状态。
名称包含关系不等于同一个概念。例如“基础货币”和“基础货币变动”是相关但不同的概念。当前 5 个候选全部是 pending，系统不会自动合并。确认前想清楚。

5.7 命题（Claims）

  • 点“从已学书籍抽取命题”，从 compiled 书里抽 claim。
  • 按关键词、状态筛选。
  • 每条命题显示主语、谓语、宾语、书名、页码、极性、置信度、逐字 quote。
  • “标记为被取代”需要输入一个已经存在的新 claim_id，并确认；旧命题变为 superseded，可回滚。
  • “确认为不同观点”用于 conflicted 命题：保留两条，恢复 active。

当前 640 条命题，自动冲突 0 组。冲突检测只是提示，不会自动改判。

5.8 溯源（Inspect）

输入 book_id、framework_id 或 chunk_id，查看 provenance 边：书 → 框架 → chunk → 概念。任何回答都应该能沿这条边走回原文。

5.9 右上角和抽屉

  • 右上角显示版本、数据库路径、健康状态。
  • 点书、分析、实体等条目，会从右侧滑出详情抽屉。
  • 按 Esc 关闭抽屉。
GUI 的边界：它负责展示、选择、导入、检索、审计、校验和记忆管理，不负责“自动生成一篇完整专家分析”。真正的综合回答由 Hermes 的大模型完成。这样做是为了让引用可验证，而不是让 GUI 假装自己读过书。

$PY = '.\.venv\Scripts\python.exe'

输出每本书的 book_id、标题、状态、学科等。只有 compiled 才算真正学过。

Hermes 是“前台”，你主要和它说话。它负责理解问题、选择工具、组织回答。BookCompiler 和 Hindsight 是它背后的“能力”。

7.1 启动前设置

Hermes 用 HERMES_HOME 找自己的配置、技能和状态数据库。每次新开 PowerShell 都建议先设置：

$env:HERMES_HOME='D:\hermes agent'

检查版本和健康：

& 'D:\hermes agent\bin\hermes.exe' --version
& 'D:\hermes agent\bin\hermes.exe' doctor

7.2 进入聊天

& 'D:\hermes agent\bin\hermes.exe' chat

然后在聊天界面里直接问。推荐从这几类问题开始：

问它读过什么

今天央行降准 50 个基点，同时地方债置换加速。结合你读过的书，从经济、政治、法律三个角度判断风险传导，并给出原文引用和页码。

7.3 一次性命令（不进聊天界面）

$env:HERMES_HOME='D:\hermes agent'
& 'D:\hermes agent\bin\hermes.exe' --yolo -z '用我读过的书分析：降准是否必然导致银行信贷扩张？请给出书名、页码和逐字引用。'

-z 是一次性提问。--yolo 表示自动批准工具调用，只应在你信任的本地环境使用；它会减少确认，但也意味着 agent 可以直接执行它决定的操作。

PowerShell 的假报错：有时命令退出码是 1，并出现 NativeCommandError，但标准输出里其实有完整回答。这是 PowerShell 把 Hermes 的 stderr 包装成错误，不一定是真失败。先看回答内容，再看退出码。

7.4 Hermes 的技能机制

技能不是“一本书一个技能”。本机有两个相关技能：

D:\hermes agent\skills\book-library\SKILL.md
D:\hermes agent\skills\book-learning-loop\SKILL.md

book-library 负责“用读过的书回答领域问题”；book-learning-loop 负责“把一本书真正读进来、校验、评分、再进化”。达尔文技能在 D:\hermes agent\skills\darwin-skill\SKILL.md，用来评估和改进技能文本本身。

它规定了：

  • 什么时候自动使用书库（新闻、政策、市场事件、“从你读过的书看”）；
  • 必须先调用 book_library 才能声称“读过”；
  • 只有 learned=true 的书才算学过；
  • 每个事实必须带书名、章节、页码和逐字引用；
  • 模式 2/3 必须先问用户使用范围；
  • 不能把经济、政治、法律的冲突平均掉；
  • 法律 lens 只是分析，不是法律意见。

这意味着你不需要每次手动说“请调用 book_library”。只要问题像“用读过的书分析这条新闻”，技能描述会触发它。

7.5 Hermes 自己的记忆和自进化

Hermes 自己也有会话、技能和自进化机制，和 BookCompiler 的进化是两层：

  • Hermes 层：怎么调用工具、怎么改进技能文本、怎么管理会话。
  • BookCompiler 层：只允许有界配置补丁（检索权重、书/框架偏好），必须有回放和回滚。

不要把“BookCompiler 自进化”理解成“模型半夜自己改代码”。它不会改书卡、引用真值、prompt 或代码。

8. 三个系统怎么对接

8.1 BookCompiler ↔ Hermes：stdio MCP

BookCompiler 暴露一个标准 MCP 服务：

python -m bookcompiler.cli --db ...\library.db mcp

Hermes 在 config.yaml 里配置它。当前实际配置是：

mcp_servers:
  bookcompiler:
    command: 'C:\Users\mybea\projects\bookcompiler\.venv\Scripts\python.exe'
    args:
      - '-m'
      - 'bookcompiler.cli'
      - '--db'
      - 'C:\Users\mybea\projects\bookcompiler\.bookcompiler\library.db'
      - 'mcp'
    env:
      PYTHONIOENCODING: 'utf-8'
      PYTHONPATH: 'C:\Users\mybea\projects\bookcompiler\src'
      HINDSIGHT_ENABLED: '1'
      HINDSIGHT_BASE_URL: 'http://127.0.0.1:8888'
      HINDSIGHT_BANK_ID: 'bookcompiler'
    enabled: true
    lazy: false

关键点：

  • command 必须是项目虚拟环境里的 Python，不是随机的系统 Python。
  • PYTHONPATH 指向项目的 src，否则 Hermes 可能找不到 bookcompiler 包。
  • PYTHONIOENCODING=utf-8 避免中文工具结果被控制台编码破坏。
  • lazy: false 表示 Hermes 启动时就连接，不等第一次调用。

12. Hindsight API 手把手

12.1 先定义一个小工具函数

PowerShell 里直接传中文 JSON 容易编码出错。用下面这个函数，把 JSON 明确编码成 UTF-8 字节再发：

function Invoke-HindsightJson {
  param(
    [string]$Method,
    [string]$Path,
    $Body = $null
  )
  $uri = "http://127.0.0.1:8888$Path"
  if ($null -eq $Body) {
    return Invoke-RestMethod -Method $Method -Uri $uri
  }
  $json = $Body | ConvertTo-Json -Depth 8
  $bytes = [Text.Encoding]::UTF8.GetBytes($json)
  Invoke-RestMethod -Method $Method -Uri $uri `
    -ContentType 'application/json; charset=utf-8' -Body $bytes
}

13. 一次真实问答的完整流程

假设你问 Hermes：

今天央行降准 50 个基点，同时地方债置换加速。结合你读过的书，从经济、政治、法律三个角度判断风险是否从财政转移到银行体系。请给出原文引用和页码。

13.1 你看到的过程

  1. Hermes 识别出这是“用读过的书分析新闻/政策”的场景，加载 book-library 技能。
  2. 调用 book_library，确认哪些书是 compiled，哪些只是 ingested。
  3. 调用 book_plan，选出相关书和框架，给出选择卡：
    • 例如《中央银行与货币供给》《以利为利》《稳定不稳定的经济》《当代中国政府与政治》；
    • 标出覆盖缺口，例如“法律类书覆盖较薄”。
  4. 如果是 auto 模式，直接继续；如果是 direction 或 books 模式，先问你三选一。
  5. 调用 book_analyze，生成多镜头 AnalysisPacket 草稿。
  6. 调用 book_recall，取出逐字引用、章节、页码和分数拆解。
  7. 内部 book_validate 逐字回查引用；找不到就报 unsupported_quote。
  8. Hermes 组织回答，明确区分：
    • 书里原文说了什么；
    • 哪些是推断；
    • 哪些是建议；
    • 经济/政治/法律三个 lens 在哪里冲突；
    • 什么条件下结论会改变。

13.2 回答应该长什么样

1. 这件事改变了什么（框架性描述，不需要引用）
2. 书里怎么说（按 lens 分节；每条主张带书名/章节/页码/逐字引用）
3. 三个 lens 在哪里冲突（明确写出，不平均掉）
4. 条件性结论（如果 A，则 B；如果非 A，则 C）
5. 什么会改变判断（具体指标/文件）
6. 实际用了哪些 learned 书（区分“引用过”和“只是推荐”）

13.3 已验证的例子

此前用 one-shot 探针问过“降准是否必然导致银行信贷扩张？”。Hermes 自动走书库，最终引用了《中央银行与货币供给》第 277 页和第 298 页的逐字原文，并明确回答“降准不是必然导致信贷扩张”。这说明“新闻/问题 → 选书 → 检索 → 引用 → 回答”的链路是通的。

另一个已验证的链路是 Hindsight 召回：Hermes 通过 mcp_hindsight_recall 正确复述了中文偏好“先给结论，再给证据；不确定时明确说不确定，不要编造”，并返回了条目 ID、类型和标签。

不要期待它每次都完美。它现在的强项是“有出处、可审计、能区分读过和没读过”；弱项是书覆盖不全、法律书薄、OCR 有噪声、reflect 不稳定。回答质量最终还取决于 Hermes 的模型和工具调用能力。

请调用 book_learn，book_id = <book_id>，max_chunks = 36。
它会把书卡、框架和逐字引用一起写进库，然后调用 book_validate 确认没有错误。

命令行等价方式：

& .\.venv\Scripts\python.exe -m bookcompiler.cli --db .bookcompiler\library.db `
  compile-llm <book_id> --max-chunks 36 --evidence-chars 1200

也可以批量读所有还没编译的书：

& .\.venv\Scripts\python.exe -m bookcompiler.cli --db .bookcompiler\library.db `
  compile-llm --all-ingested --max-chunks 36 --evidence-chars 1200

book_learn 做四件事：从全书均匀抽样章节 → 让阅读模型提出 BookCard 和 3–8 个 FrameworkCard → Python 逐条核对 chunk_id + quote + chapter + page → 只有全部通过才写入主库。

4

校验

& .\.venv\Scripts\python.exe -m bookcompiler.cli --db .bookcompiler\library.db `
  validate --book <book_id>

输出 [] 才算通过。出现 unsupported_quote 说明引用没能在原文逐字找到；不要绕过校验，改引用或标成推断。

5

重建实体、命题和 GraphRAG

& .\.venv\Scripts\python.exe -m bookcompiler.cli --db .bookcompiler\library.db entities align
& .\.venv\Scripts\python.exe -m bookcompiler.cli --db .bookcompiler\library.db claims build --limit-per-book 120
& .\.venv\Scripts\python.exe -m bookcompiler.cli --db .bookcompiler\library.db graphrag build

新书的概念进入实体图谱，命题进入检索与冲突检测，GraphRAG sidecar 重新计算社区和边。

6

确认它真的“学会”了

& .\.venv\Scripts\python.exe -m bookcompiler.cli --db .bookcompiler\library.db books
& .\.venv\Scripts\python.exe -m bookcompiler.cli --db .bookcompiler\library.db coverage

状态应该是 compiled，书卡状态是 verified，并且至少有一个 framework。只有这时 book_recall / book_analyze 才会把它当已学习证据。

三个必须知道的边界：
  1. 代表样本，不是逐页全文。book_learn 默认抽 28–36 个证据块，覆盖全书章节，但不是把每一页都塞给模型。
  2. verified 是机器逐字溯源，不是人工盲评。它证明引用在 OCR 文本里逐字存在；不能证明 OCR 每个字都对。
  3. 读书默认不允许走 DeepSeek。如果 reader 解析到 DeepSeek 端点，会直接报错；除非显式设置 BOOKCOMPILER_READER_ALLOW_DEEPSEEK=1。这是防误刷费用的硬闸。

15. 自进化是什么、不是什么

15.1 它现在能做什么

  • 从结构化反馈中生成 proposal：错误模式、偏好书/框架、缺失证据、低分分析。
  • 提案有 evidence_feedback_ids、risk、rollback、gate。
  • 状态机：proposed → accepted → shadow → promoted → rolled_back，也可以 rejected。
  • 晋升必须有结构回放报告，且所有 case 通过。
  • 应用前写快照，失败可恢复；支持 rollback。
  • 只允许三类变更：检索权重、书偏好、框架偏好。

15.2 它不能做什么

  • 不会自动改写 BookCard、FrameworkCard、引用或代码。
  • 不会自动改逐字引用校验规则。
  • 不会因为一次低分就把某本书永久拉黑。
  • 不会在没有回放报告的情况下晋升。
  • 不会做真正的 shadow/canary 流量和盲评（还没实现）。

15.3 为什么这么保守

书籍分析系统最危险的不是“回答不够聪明”，而是“编造引用”“把某本书的观点压成错误口号”“把框架用在不适用的条件下”“把三个镜头的冲突平均掉”。所以真值契约不能学习：引用校验、法律免责声明、冲突处理规则必须固定。

15.4 当前状态

本机书库目前 feedback=0、evolution_proposals=0，所以自进化链路还没有用真实反馈跑过。代码和测试在，但没有“已经进化出更好配置”的证据。不要声称它已经通过自进化变强。

15.5 怎么试

  1. 对一份分析打分并写反馈（GUI 分析详情底部，或 CLI feedback）。
  2. 运行 evolution-propose --min-support 1。
  3. 查看 proposal，决定 accept / reject。
  4. 如果 accept，进入 shadow；准备回放 cases。
  5. 回放全通过后，才能 promote。
  6. 不满意就 rollback。

记住：结构回放通过只证明“没有结构退化”，不证明“答案质量更好”。真正的盲评还没做。

16. 常见错误与修复

16.1 连不上 Hindsight（8888）

现象：Invoke-RestMethod http://127.0.0.1:8888/health 报连接失败。

修复：

  1. 确认 Hindsight 进程在跑：Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*run_server.py*' }
  2. 启动：cd D:\hindsight; .\.venv\Scripts\python.exe .\run_server.py
  3. 看日志：Get-Content -Tail 80 D:\hindsight\server.log
  4. 检查 5432 是否被别的 PostgreSQL 占用。Hindsight 使用 pg0-embedded 嵌入版 PostgreSQL，实例名 hindsight；可用 python -c "import pg0; pg0.start('hindsight')" 启动。若提示密码错误，请核对 D:/hindsight/.env 里的数据库连接串。

16.1b 读书时 MiMo 返回 high risk 被拒

现象：compile-llm 失败，.bookcompiler/compilations/<book_id>.raw.json 里是 status=rejected、reason 含 high risk。

原因：这是模型服务商的内容安全层，不是书库校验失败，也不是代码 bug。

修复：

  1. 先重试一次，并把证据包调小：compile-llm <book_id> --max-chunks 20 --evidence-chars 900。
  2. 项目已经在 prompt 里加了“授权学术编译任务”的说明，通常会降低误判。
  3. 仍被拒时改用本地 Ollama：compile-llm <book_id> --provider ollama --model qwen2.5:14b-instruct-q4_K_M --base-url http://127.0.0.1:11434。慢，但不花钱。
  4. 不要为了绕过拒绝改用 DeepSeek；读书路由默认会被硬闸拦住。

16.2 连不上 Ollama（11434）

现象：Hindsight 启动或 retain 报模型连接错误。

修复：确认 Ollama 在运行；ollama list 能看到 qwen2.5:7b-instruct-q4_K_M；必要时 ollama serve。不要改 Hindsight 的 base URL 结尾 /v1。

16.3 Hindsight 报 UnicodeEncodeError / gbk

现象：直接运行 hindsight-api.exe 时出现 UnicodeEncodeError: 'gbk' codec can't encode character ...。

修复：用 D:\hindsight\run_server.py 启动；它会设置 UTF-8 输出。也可以设置 $env:PYTHONUTF8=1 和 chcp 65001。

16.4 Hermes 报 NativeCommandError，但回答正常

现象：PowerShell 退出码 1，红色错误，但标准输出里有完整中文回答。

原因：PowerShell 把 Hermes 的 stderr 当成错误记录。不是书库调用失败。

修复：先看回答内容；需要脚本化时用 2>&1 合并输出，或忽略退出码，检查输出里是否有预期内容。

16.5 Hermes 找不到 bookcompiler 工具

检查：

$env:HERMES_HOME='D:\hermes agent'
& 'D:\hermes agent\bin\hermes.exe' mcp test bookcompiler

如果失败：

  • 确认 config.yaml 里的 Python 路径存在；
  • 确认 PYTHONPATH 指向 C:\Users\mybea\projects\bookcompiler\src；
  • 确认 library.db 路径存在；
  • 手动跑 python -m bookcompiler.cli --db ... mcp 看是否报错。

16.6 输入中文变成问号/乱码

原因：Windows 控制台代码页、PowerShell 原生参数编码、或文件写入编码不一致。

修复：

  • 优先用 GUI（浏览器统一 UTF-8）。
  • 用 PowerShell 7 / Windows Terminal。
  • 设置 [Console]::OutputEncoding=[Text.UTF8Encoding]::new($false) 和 chcp 65001。
  • 写文件用 [IO.File]::WriteAllText($path,$text,[Text.UTF8Encoding]::new($false))，不要用默认编码的 Set-Content 写中文。

16.7 GUI 打不开 / API 500

  1. 确认进程：Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*bookcompiler*gui*' }
  2. 看日志：Get-Content -Tail 80 .bookcompiler\gui.out.log
  3. 检查 http://127.0.0.1:8765/api/status。
  4. 重启 GUI。

16.8 分析返回 409 confirmation_required

这不是错误，是同意门。模式 direction / books 必须先选：specified、specified+recommended 或 recommended。选完再提交。

16.9 编译报 unsupported_quote

引用没有在原文里逐字找到。可能原因：

  • 改了标点/空格；
  • OCR 识别错字；
  • 页码/章节归属错；
  • 引用了另一本书的句子。

修复：回到 book_recall 的逐字 quote，或把该句标成推断。不要关闭校验。

16.10 Hindsight native plugin 安装失败（GitHub 443）

这是网络问题，不是配置问题。当前用 MCP 直连已经可用，不需要 native provider。等网络恢复后再考虑：

hermes plugins install hindsight --yes-deps --enable

安装前先备份 D:\hermes agent\config.yaml。

16.11 reflect 超时

当前 7B 本地模型上 reflect 不可靠，曾 300 秒超时。不要把它接进自动化。需要时先用 retain/recall；reflect 等模型/配置优化后再试。

16.12 书显示 ingested，不能当证据

正常。它只是入库，没有书卡/框架卡。按第 14 节完成 compile + validate，状态变 compiled 后才算 learned。

17. 备份、恢复、重置

三套系统各有自己的数据，备份要分开做。最重要的一条：备份前先停写入，不要在服务运行时直接复制数据库文件。

17.1 备份 BookCompiler

  1. 停止 GUI（关闭启动它的窗口，或结束对应 python 进程）。
  2. 复制整个数据库文件：
$src = 'C:\Users\mybea\projects\bookcompiler\.bookcompiler\library.db'
$dst = "D:\backup\bookcompiler-$(Get-Date -Format yyyyMMdd-HHmm).db"
New-Item -ItemType Directory -Force (Split-Path $dst) | Out-Null
Copy-Item -LiteralPath $src -Destination $dst
Get-Item $dst | Select-Object FullName,Length

如果目录里有 library.db-wal / library.db-shm，也要一起复制。本机当前没有这两个文件。

17.2 备份 Hermes

停止 Hermes 后，复制：

  • D:\hermes agent\state.db（会话/状态）
  • D:\hermes agent\config.yaml（配置）
  • D:\hermes agent\skills\（技能）
$dst = "D:\backup\hermes-$(Get-Date -Format yyyyMMdd-HHmm)"
New-Item -ItemType Directory -Force $dst | Out-Null
Copy-Item -LiteralPath 'D:\hermes agent\state.db' -Destination $dst
Copy-Item -LiteralPath 'D:\hermes agent\config.yaml' -Destination $dst
Copy-Item -LiteralPath 'D:\hermes agent\skills' -Destination $dst -Recurse
不要把 D:\hermes agent\.env 和 auth.json 复制到公共云盘或 Git 仓库。如果备份它们，必须加密并妥善保管。

17.3 备份 Hindsight（推荐 pg_dump）

Hindsight 用 PostgreSQL，最稳的备份方式是 pg_dump。本地连接凭据在同目录的 instance.json 里，教程不把密码写死。

$inst = Get-Content -Raw 'C:\Users\mybea\.pg0\instances\hindsight\instance.json' | ConvertFrom-Json
$env:PGPASSWORD = $inst.password
$pgdump = 'C:\Users\mybea\.pg0\installation\18.1.0\bin\pg_dump.exe'
$dst = "D:\backup\hindsight-$(Get-Date -Format yyyyMMdd-HHmm).dump"
New-Item -ItemType Directory -Force (Split-Path $dst) | Out-Null
& $pgdump -h 127.0.0.1 -p 5432 -U $inst.username -d $inst.database -Fc -f $dst
Remove-Item Env:PGPASSWORD
Get-Item $dst | Select-Object FullName,Length

17.4 文件级备份 Hindsight

如果一定要复制数据目录：

  1. 先正常停止 Hindsight 进程。
  2. 确认 5432 不再监听。
  3. 复制整个 C:\Users\mybea\.pg0\instances\hindsight\data。

不要在 PostgreSQL 还在写的时候复制数据目录，可能得到不一致的备份。

17.5 恢复 Hindsight

pg_restore --clean --if-exists 会覆盖现有数据。先备份当前库，再操作。 
$inst = Get-Content -Raw 'C:\Users\mybea\.pg0\instances\hindsight\instance.json' | ConvertFrom-Json
$env:PGPASSWORD = $inst.password
$pgrestore = 'C:\Users\mybea\.pg0\installation\18.1.0\bin\pg_restore.exe'
& $pgrestore -h 127.0.0.1 -p 5432 -U $inst.username -d $inst.database --clean --if-exists 'D:\backup\你的备份.dump'
Remove-Item Env:PGPASSWORD

17.6 恢复 BookCompiler / Hermes

先停止对应服务，把备份文件复制回原路径，再启动。不要在两个进程都在写的时候覆盖数据库。

17.7 重置

不要直接删库。推荐做法：

  • BookCompiler：停止 GUI，把 library.db 改名成 library.db.bak，再运行 init 创建新库。
  • Hermes：停止 Hermes，把 state.db 改名备份。你会丢失会话历史。
  • Hindsight：先用 API 清空指定 bank 的 memories，或删除 bank；不要直接删 PostgreSQL 数据目录。

任何重置前，先做一次可用的备份。

22.4 人类学习方法怎么用到这里

不要只把“费曼学习法”当口号。可落地的是五步循环：

1
先出题，不先查书。 让 agent 先写“我猜答案是什么、我需要哪些证据、哪里不确定”。这对应 retrieval practice / pretesting。
2
带引用地读和编译。 book_ingest → book_export_text → book_compile → book_validate，每条关键主张有逐字 quote。
3
费曼式复述。 不看原文，用大白话解释；卡住的地方回查章节。对应 self-explanation。
4
迁移到新事件。 用当天新闻/政策/市场事件做 book_analyze，问“哪个框架适用、哪里冲突、什么会推翻结论”。对应 transfer。
5
评分、练弱项、间隔复习。 reading-eval → reading-report → reading-propose；弱项变成具体练习，再排进复习队列。

Retrieval practice闭卷先答，再 book_recall 对照未固化
Spaced repetition书卡/框架/claim 加复习队列未实现

22.5 多智能体怎么用

能用到，但重点不是“多开几个模型”，而是把不同职责拆开，减少自说自话。最划算的第一版是：

检索者 -> 反方 -> 盲评 judge
角色只负责什么对应工具
Planner / 出题者拆子问题、列需要的证据和镜头book_plan
Retriever按子问题召回 chunk/claim/实体book_recall
Feynman explainer不看原文，用大白话解释问题 + 书卡/框架卡
Red team找反例、失败条件、被忽略的镜头book_analyze
Citation auditor逐字核对 quote/章节/页码book_validate
Judge按九维 rubric 盲评book_reading_eval
Evolver把重复弱项变成提案book_evolution

风险：群体思维、错误放大、上下文污染、成本爆炸、假共识、提示注入。纪律：judge 不能看作者解释；反方不负责最终答案；引用审计只认原文；综合者不能平均冲突。

当前边界：多智能体目前是研究文档和手工编排协议，不是运行时自动编排。项目里还没有“九个 agent 在后台自动分工”；上面的角色表是下一阶段的实现蓝图。

成本大致是：单 agent 1x；三角色 2–3x；五角色 3–5x；九角色 5–10x。只有高风险、低置信或对外交付才值得上完整链路。完整协议见 docs/MULTI-AGENT.md。

22.6 高级 RAG：GraphRAG 等能不能用

GraphRAG 已经落地，但用的是轻量、确定性的 sidecar 方案，不是 Microsoft 全量 LLM GraphRAG。它复用已有的实体、claim、framework、chunk 构图，单独存 .bookcompiler/library.graph.db；检索用 hybrid + graph 的 RRF 融合；图不可用时自动回退 hybrid，不会让分析失败。它已经接进 book_analyze 主链路，也有 CLI、MCP 和 GUI 入口。

方案适合主要风险建议
GraphRAG实体/社区/全局问题实体噪声、未必优于简单 RAG已落地（轻量 sidecar）
LightRAG轻量图检索、增量更新仍依赖实体质量值得参考
HippoRAG记忆型多跳检索图构建和评测成本方向接近
RAPTOR长书层级摘要摘要幻觉、引用回溯摘要只做导航
Self-RAG / CRAG判断证据够不够、要不要重查自评偏差、额外调用优先做

Microsoft GraphRAG 的 README 已明确说项目“largely in maintenance mode”，不建议作为新系统底座。图检索必须和简单 hybrid RAG 做同条件对比。详细项目清单和论文见 docs/RAG-LANDSCAPE.md。

22.7 信息源缺口提示：知道自己没读什么

这一轮最重要的修复，不是“多推荐一本书”，而是区分学科覆盖和权威原文覆盖。书库里有《中央银行与货币供给》，不代表它有《中华人民共和国中国人民银行法》；有财政学教材，也不代表它有《预算法》原文。

当问题涉及权限、程序、监管边界或债务约束，而书库缺少相应权威文本时，系统会在选择卡、analysis memo、MCP 回值和 GUI 里显示：

  • 缺哪一部法律、行政法规、监管规章或正式政策文件；
  • 为什么这个问题需要它，命中了哪些问题词；
  • 建议入库的学科标签；
  • 官方版本核对来源；
  • 一条可复制修改的 bookcompiler ingest 命令；
  • 入库后应该重新检查什么。
bookcompiler --db .bookcompiler\library.db source-gaps `
  --query "如果中国央行降准，银行信贷是否必然扩张？请从货币政策、地方财政和金融监管三个角度分析。" `
  --lenses economics politics law `
  --format text

预期会看到《中华人民共和国中国人民银行法》《中华人民共和国商业银行法》《中华人民共和国银行业监督管理法》。如果书库已经有同名法规（哪怕只是 ingested、尚未编译），系统不会重复让你下载；它会继续缺什么补什么。

边界：它只提示，不自动联网下载，也不把未入库的法规写进 citations。你需要先把官方现行有效文本下载到本地，再走 ingest → export-text → compile → validate。只有这样，下一轮分析才真的能引用它。

MCP 的 book_plan / book_analyze 会返回 source_recommendations，工具描述要求调用方明确告诉用户，不能假装“已经读过”。详细目录和设计见 docs/SOURCE-GAPS.md。
