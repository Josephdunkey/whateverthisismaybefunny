LOCAL KNOWLEDGE COMPILER

她读过哪些书，
为什么这样回答。

不是把整本书塞进上下文，而是把书里的论证条件、失败边界和原文证据编译成可调用的判断框架。每一次分析都能回到具体章节和原文。

三条边界

  1. 不自动下载书。导入本地文件，或由你明确批准。
  2. GUI 不冒充大模型。深度编译与分析补丁仍由 agent 写入。
  3. 没有原文引用的结论，验证器会拒绝。

MODEL CONTROL

模型切换中心

三个独立模型槽：Hermes 负责阅读与对话，BookCompiler 只负责独立盲评，Hindsight 负责记忆抽取。换模型不会自动迁移旧向量或旧记忆。

一键预设

会先备份配置文件

三种预设：MiMo 云端、DeepSeek 云端、全部本地。云端预设只让 Hermes 与 BookCompiler 盲评走云端；Hindsight 仍走本地 Ollama。工具只写 provider / model / base_url，不读取、不显示 API key。改完 Hermes 与 Hindsight 都需要重启对应服务。

环境变量到底怎么生效

        
    
          
  • 系统环境变量 / 用户环境变量：只对新启动的进程生效，已打开的 GUI、终端、Hermes 不会自动刷新。
    • 
          
  • 项目 .env：BookCompiler 启动时读取；比系统变量更适合做默认值。
    • 
          
  • 命令行参数 / GUI 输入框：优先级最高，适合单次切换。
    • 
          
  • Hermes 的模型在 D:\hermes agent\config.yaml；Hindsight 的模型在 D:\hindsight\.env；BookCompiler 盲评在项目 .env。
